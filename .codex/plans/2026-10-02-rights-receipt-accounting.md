# Tranche 18 — explicit rights receipt accounting

Issue: https://github.com/4444J99/github-engineering-standards/issues/18

The existing complete triage queue is not clearance, and recovery currently has no rights acceptance input. Add an optional, fail-closed adapter without inventing human decisions.

1. Write negative and positive synthetic tests first; observe the absent adapter failure.
2. Validate the complete locked artifact inventory, receipt identity/digests, separately supplied approved authority policy, distinct rights reviewer/independent auditor/human acceptor roles, evidence timestamps, explicit use/obligations, exception disposition and exact scoped distribution approval.
3. Bind every evidence document to the same inventory, artifact, use and distribution scope. Reject missing, changed, duplicate, future, unsafe-path and unauthorized evidence. Recheck all evidence bytes before returning accounting.
4. Integrate paired optional receipt/policy inputs in recovery. With no real inputs, clearance stays unknown and zero. Machine validation checks accountable attestations, not legal truth, authority authenticity or publication behavior. Published-body rights remain separate.
5. Run required tests/validation/compilation, real recovery and provenance checks. Commit and push all authored work, verify remote parity, post exact issue receipt. Do not create approval grants or publish anything.
