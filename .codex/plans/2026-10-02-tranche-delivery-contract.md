# Tranche delivery contract

User instruction received 2026-10-02: create an issue, commit and push per tranche, for all changes.

- Create a scoped GitHub issue before each new tranche; use existing issue for corrective/completion slices of that tranche.
- Commit and push all agent-authored changes in the tranche, including plans and evidence. Preserve unrelated user work; stage explicit known paths.
- Post exact commit and observed verification evidence to the issue. Mark draft/incomplete work explicitly; never label a checkpoint as a completed review or gate.
- Run the repository-required unittest, validate and compile commands once per integrated tranche. Record provenance/recovery results at their actual scope.
- Keep issues open for human closeout. Human-required rights, native and estate approvals are not granted by issue creation.
