## GES interpretation: authority and limits

Use the examples for welcoming presentation, onboarding and contribution design.
Keep example commands, stack names, feature placeholders, deployment services,
support mechanisms and reviewer requirements distinguishable from universal rules.

The model does not prove that a consumer project uses npm, deploys to a named
service, accepts donations or has an operational application. Example identities
and unrelated project links must not become consumer facts. No upstream setup or
deployment commands were executed.

## Synthesis obligations

Render only project-supported sections and supply truthful local parameters.
Review contribution obligations separately from presentation structure; record
explicit local adoption before enforcing sample review or release requirements.
